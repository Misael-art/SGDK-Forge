## Caminhos e estrutura: achados adjudicados

- `forward-kinematics-rigging:24`: `sdk/sgdk-2.11/inc/fixmath.h` não existe no SDK local; `maths.h` existe. Proposta: apontar ao header real e verificar símbolos usados. É falha concreta, não ausência de documento do projeto.
- `sprite-animation:415`, `aaa-pipeline-guardian:81`, `project-learning-loop:79`: referências curtas `references/...` resolvem na árvore central `.agent`, não ao lado dessas skills. Destinos centrais existem; ambiguidade de base, não três arquivos necessariamente perdidos. Propor caminhos explícitos.
- `tdd-authoring:29` cita `references/sgdk_211_api_reality.json` no contexto explícito de sgdk-runtime-coder: resolvido nessa skill, não classificado como podre.
- `doc/11-gdd.md`, `doc/13-spec-cenas.md`, manifests e outputs de projeto não devem ser buscados apenas na raiz do workspace. O inventário bruto marca existência no escopo indicado, não blocker automaticamente. Aplicar resolução project-root/skill-root/framework-root antes de denunciar caminho quebrado.
- Descrições e seções de aceite são frequentes; a falha principal é integração com dados reais, não falta generalizada de templates. Skills longas precisam índice de rotas e casos pequenos, não mais prosa duplicada.

## Rota MUGEN proposta

Intake/hash/permissão → diagnóstico e perfil suportado → parser/IR e loss manifest → art-conversion + pixel-strict → orçamento composto VDP/CPU → runtime-coder + input/collision + fighting opt-in → xgm2-audio-director → code-reviewer → evidence-curator/audiovisual_review → guardian → learning-loop.

Cada seta deve carregar hash e artefato, não apenas nome de skill. Build não pode consumir assets com perdas desconhecidas; aprovação humana é necessária para aceitar aproximação visual, não para o agente esconder a perda.
